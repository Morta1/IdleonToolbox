# Goals 2: UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Users add goals on the bubbles, stamps, grimoire, compass, tesseract and armory pages through one shared popover, and see and manage them in a dashboard Goals section.

**Architecture:** One hook (`useGoals`) owns storage; one popover (`GoalPopover`) is assembled from parts switched on by the system's descriptor; `SetGoalButton` sits on entries; `AddGoalButton` is rendered once in the NavBar beside "Pin this page" for any route that has a descriptor. The dashboard renders `resolveGoals` output.

**Tech Stack:** React (`.jsx`), MUI, `@mantine/hooks` `useLocalStorage`, vitest + Testing Library (jsdom), Browser pane on `http://localhost:3001?demo=true`.

**Spec:** `docs/superpowers/specs/2026-10-20-dashboard-goals-design.md`

Depends on plan 1 (`utility/goals/*`).

## Global Constraints

- Everything from plan 1's Global Constraints.
- Storage only through `useLocalStorage` (key `GOALS_STORAGE_KEY`); nothing read from storage during the first render (static export hydration: mantine reads in an effect by default, keep it that way).
- No goal UI when `accountKeyOf(state)` is `null` (logged out, `?profile=`).
- Tooltips hang off an InfoIcon and use `@components/Tooltip`; no hidden plain-text tooltips; no state chips; no `image-rendering: pixelated`.
- Copy is sentence case, no em dashes, no apostrophes in patch notes.
- UI-visible tasks end with a Browser pane screenshot at 1920x950 and 384x832.

## Review Focus

1. `?profile=` view: no `AddGoalButton`, no `SetGoalButton`, dashboard section hidden; nothing written to storage. Test in Task 1 (`useGoals`) and Task 3.
2. Touch devices (`hover: none`): entry icons must be reachable without hover. Test in Task 3 (CSS media query asserted via class) and checked at 384x832.
3. Saving a target above an absolute max, or a percent `>= 100`, is blocked with an inline message. Test in Task 2.
4. Editing an existing goal from its entry icon updates it, never adds a second one. Test in Task 2.
5. Dashboard with goals for an account, then switching to another account (different first character): the other account sees only its own goals. Test in Task 1.
