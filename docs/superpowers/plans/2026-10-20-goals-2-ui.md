# Goals 2: UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Users add goals on the bubbles, stamps, grimoire, compass, tesseract and armory pages through one shared popover, and see and manage them in a dashboard Goals section.

**Architecture:** One `GoalsProvider` (in `_app`, data-free) owns storage and exposes `useGoals`. One popover (`GoalPopover`) is assembled from parts switched on by the system's descriptor. `SetGoalButton` sits on entries. `AddGoalButton` is loaded with `next/dynamic` from the NavBar only on routes listed in the data-free `GOAL_ROUTES`, so pages without goals (wiki, static pages) never download the registry or parsers. The dashboard renders `resolveGoals` output.

**Tech Stack:** React (`.jsx`), MUI, `@mantine/hooks` (`useLocalStorage`, `readLocalStorageValue`), vitest + Testing Library (jsdom), Playwright e2e, Browser pane on `http://localhost:3001?demo=true`.

**Spec:** `docs/superpowers/specs/2026-10-20-dashboard-goals-design.md`

Depends on plan 1 (`utility/goals/*`).

## Global Constraints

- Everything from plan 1's Global Constraints.
- Storage only through `@mantine/hooks`: `useLocalStorage` (key `GOALS_STORAGE_KEY`) for live state; `readLocalStorageValue` inside an effect for one-off flags. Nothing read from storage during the first render (static export hydration).
- Nothing imported by `_app`, `NavBar` or `GoalsProvider` may import parsers, `@website-data` or `utility/goals/registry` statically. `e2e/chunk-audit.spec.js` and `e2e/hydration.spec.js` are the gates.
- No goal UI when `accountKeyOf(state)` is `null` (logged out, `?profile=`, empty account).
- Tooltips hang off an InfoIcon and use `@components/Tooltip`; no state chips; no `image-rendering: pixelated`.
- Copy is sentence case, no em dashes.
- UI-visible tasks end with Browser pane screenshots at 1920x950 and 384x832.

## Review Focus

1. `?profile=` view: no `AddGoalButton`, no `SetGoalButton`, dashboard section hidden; nothing written to storage. Test in Task 1 and Task 3.
2. Wiki and static pages download no goal registry or parser chunk. Gate: `npm run test:e2e` in Task 3.
3. Saving a target above an absolute max, or a percent `>= 100`, is blocked with an inline message. Test in Task 2.
4. Editing an existing goal from its entry icon updates it, never adds a second one. Test in Task 2.
5. Hiding the Goals dashboard filter survives reloads (the one-time "add Goals to saved filters" step must not re-add it). Test in Task 4.
